# HQ 차량 운행 현황 — 학교/아파트 토글 캠퍼스 스코프 버그 수정 (2026-06-10)

## 증상
HQ → 캠퍼스 → **차량 운행 현황**(`hq/campuses/[id]/vehicles`)에서 **대치 캠퍼스**의 학교/아파트 토글을 눌러도 아무것도 안 뜸. (중계·정발은 각 캠퍼스 원장 계정으로 직접 로그인해 보므로 정상)

## 근본 원인 (데이터 문제 아님)
- 대치 학생의 school/apartment 데이터는 2026-06-08 동기화로 DB에 정상 존재(132명, 검증 완료). **데이터 문제가 아니라 화면(HQ) 캠퍼스 스코프 코드 버그.**
- 학교/아파트 토글 데이터 출처 = `/api/campus/students?schools=1|apartments=1`.
  - 이 GET은 `profile.campus_id`(로그인 사용자 캠퍼스)로만 스코프하고 **`campus_id` 파라미터를 받지 않음**. HQ 계정은 `campus_id`가 비어 있어 `400 캠퍼스 없음` 반환.
  - `RouteMapView.tsx`의 해당 fetch(약 450행)도 **`campusId`를 안 넘김**(place-spots 등 다른 fetch는 넘기는데 여기만 누락).
- 결과: HQ로 보는 **모든** 캠퍼스의 학교/아파트 토글이 빔. 대치가 걸린 이유 = 전용 원장 로그인 없이 HQ로 봐서.

## 수정 (place-spots와 동일 패턴)
1. **`app/api/campus/students/route.ts` GET** — HQ 폴백 추가:
   ```ts
   let campusId: string | null | undefined = profile?.campus_id
   if (!campusId && profile?.role === 'hq_admin') campusId = new URL(request.url).searchParams.get('campus_id')
   if (!campusId) return NextResponse.json({ error: '캠퍼스 없음' }, { status: 400 })
   ```
   - 일반 캠퍼스 사용자는 항상 자기 campus_id로 스코프 → `?campus_id` 파라미터 무시(권한 우회 불가). hq_admin만 파라미터 사용.
2. **`app/(campus)/campus/vehicles/RouteMapView.tsx`** (학교/아파트 목록 fetch) — `campus_id` 전달 + deps `[campusId]`:
   ```ts
   const cq = campusId ? `&campus_id=${campusId}` : ''
   fetch(`/api/campus/students?schools=1${cq}`)…
   fetch(`/api/campus/students?apartments=1${cq}`)…
   ```

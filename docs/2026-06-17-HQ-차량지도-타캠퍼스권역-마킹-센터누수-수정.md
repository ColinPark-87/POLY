# HQ 차량지도 — 타캠퍼스 권역 마킹 누수 + 일부캠퍼스 애매하게 뜸 (2026-06-17 2차)

## 증상
1차 수정(campus_id 전달) 배포 후 HQ 차량운행현황에서:
- 대전·목동·분당·송도·송파·운정·정발이 **애매하게 뜨거나 안 뜸**.
- 일부 마킹이 **타캠퍼스 권역까지 확대되어** 표시됨. **HQ에서 볼 때만** 발생.

## 근본 원인 (2가지 독립 원인)

### 원인 A — 캠퍼스 전환 시 옛 캠퍼스 센터로 지오코딩 (HQ 전용)
HQ는 `/hq/campuses/[id]/vehicles`에서 캠퍼스 A→B 이동 시 **RouteMapView 인스턴스를 재사용**하고 `campusId` prop만 바뀜.
지오코딩 effect가 지도 센터를 `coordsRef.current[campusName] ?? Object.values(coordsRef.current)[0]`로 계산하는데,
전환 직후 `coords`/`coordsRef`에는 **B의 DB좌표가 아직 안 들어와 A의 좌표가 남아있음**(stop-coords fetch는 비동기).
→ `Object.values(A좌표)[0]` = **A 캠퍼스 stop이 센터로 잡힘** → B의 아파트를 A 중심 5km 반경으로 지오코딩
→ A 근처 B아파트만 매칭(타캠퍼스 권역에 찍힘)·B 진짜 아파트는 미매칭(안 뜸).
게다가 `schoolGeocodedRef=true`로 잠겨 좌표 도착 후 재지오코딩 안 됨 + 잘못된 결과가 localStorage 캐시에 **저장(오염)**.
→ 캠퍼스단위 로그인은 단일 캠퍼스만 로드(타캠퍼스 좌표 없음)라 **구조적으로 무관**.

### 원인 B — 아파트명 데이터 잡음 (목동 등)
센터 좌표는 7개 캠퍼스 모두 정상(검증 완료). 그러나 **목동 837개 중 656개 아파트명에 `[2026 차]` 운영태그**가 붙어
지오코딩 쿼리를 오염시켜 매칭 실패 → 목동 마킹 누락. (운정 IPARK·송도 센트럴파크 등 generic 브랜드명·표기변형도 보조 원인.)

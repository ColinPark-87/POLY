# 차량관리 지도 — 호차 명단 카드(학생설정 풀편집·플로팅) 신규

날짜: 2026-06-08
대상: `/campus/vehicles` (RouteMapView)
상태: 구현 완료, **미배포** (운영 중 → 백업 선행·비파괴)

## 요청 / 배경
- 기존 좌상단 **"정류장 학생"** 패널은 지도에서 **정류장(stop)** 을 눌러야 그 정류장 탑승생만 보인다.
- 사용자 요청: 그것 말고, **선택한 호차(bus)의 전체 탑승생**을 **학생설정(master, 평소 고정 배정)** 기준으로 한 화면에 보고, **거기서 바로 수정**까지 되는, **현재 리모컨 크기 정도의 플로팅 카드**를 정류장 카드 아래로 띄우고 **접거나 끄기** 가능하게.
- 결정 사항(브레인스토밍):
  - 핵심 차이 = **정류장 단위 → 호차 단위 전체 명단**.
  - 데이터 = **학생설정(master)** 기준 (오늘 당일 변경 반영 X).
  - 선택 연동 = 현재 정류장 패널 선택(호차/세션/방향)을 **양방향 연동**.
  - 표시 = 리모컨 스타일 플로팅(드래그 이동·접기·끄기, localStorage 기억), 페이지 무관 토글.
  - 편집 깊이 = **풀**(요일별 다른 호차·정류장·시간 포함).

## 재사용한 기존 자산
- `getP2BusStudents(bus, dir, sessionFilter)` — 호차의 세션별 전체 탑승생을 master 데이터에서 반환.
- `p2MasterGroups`(= `bothDirGroups` 파생, `?master=true`) — 저장 후 `refreshBothDirGroups()`로 갱신하면 카드도 자동 반영.
- API `update_enrollment_schedule`(이미 풀 편집 지원: `day_buses`/`day_locations`/`day_times`), `remove_rider`.
- 리모컨 드래그/최소화/ localStorage 패턴.

## 변경 내용
### 1) 순수 함수 + 테스트 (신규)
`lib/utils/vehicle-schedule.ts`
- `buildScheduleUpdate(state)` — 편집 상태 → 저장 POST 바디.
  - **단일 호차 모드**: `{ days, bus_name, old_bus_name, location, pickup_time }`.
  - **요일별 호차 모드**: 원본(`orig`) 대비 **변경된 요일만** `day_buses`/`day_locations`/`day_times` 전송. 변경 안 한 요일은 건드리지 않아 **다른 호차/복수 enrollment 요일을 보존**(기존 모바일 `handleSaveDayBus` 계약을 미러).
  - 탑승 해제 요일 = `day_buses[d]=''`(서버가 제거). 새 요일은 장소·시간을 공통값으로 채움.
- `detectPerDay(...)` — 요일별로 호차/장소/시간이 다르면 true(요일별 모드 자동 진입용).
- `tests/vehicle-schedule.test.ts` — 15개(단일/요일별 diff/제거/no-op/감지).

### 2) RouteMapView (수정)
- 상태: `rosterOpen/rosterMin/rosterPos`(localStorage), `rosterBus/rosterSession/rosterDir`, 인라인 에디터 `rEdit*`.

- `handleRosterEditSave` — `buildScheduleUpdate`(+`orig`)로 저장 → `refreshBothDirGroups()+loadData()` 동기 갱신. `remove_rider`로 삭제.

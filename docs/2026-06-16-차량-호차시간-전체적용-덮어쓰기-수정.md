# 2026-06-16 — 호차 시간 "전체 적용"이 다른 호차 요일 시간까지 덮어쓰는 버그

## 증상 (사용자 보고)
- 차량관리 스케줄 수정에서 **승차/하차 시간 변경 → "전체 적용"** 클릭 시, **해당 호차 시간만 바뀌어야 하는데 다른 호차 시간까지 같이 변경**됨.
- 재현: 중계캠퍼스 **3호차 한휘**. 한휘는 **월=3호차, 화수목금=6호차**(요일별 다른 호차) 탑승.
  3호차 하차시간을 바꾸면 **6호차를 타는 날(화수목금) 하차시간이 3호차 변경시간과 똑같이 따라 저장**됨.

## 근본 원인
스케줄 시간 저장 불변식 = **"공유 `_time` XOR 요일별 `{요일}_time` 중 하나만"** (차량관리는 `_time`, 개설반현황은 요일별 우선).
일괄/추가 핸들러들이 무조건 아래처럼 **공유 `_time`을 통째로 덮고 요일별 시간을 삭제**해, 요일별로 다른 호차를 타는 학생은 공유 `_time`이 **모든 요일에 적용**되어 다른 호차 요일 시간까지 바뀌었다.
```ts
sched['_time'] = new_time
clearPerDayTimes(sched)   // 요일별 {요일}_time 전부 삭제
```
이미 `update_enrollment_schedule`(학생설정 탭 저장)은 `applyEnrollmentSchedule`로 이 불변식을 지켰지만, **다음 3개 핸들러에 같은 패턴이 남아 있었다**:
- `bulk_update_location_time` — 스케줄 수정 모달의 **"전체 적용"**(사용자 보고 경로)
- `bulk_set_time` — 호차 카드 "시간 일괄 설정"
- `add_rider` — 탑승자 추가 시 시간 지정
- `approve_change_request` — 차량변경 요청 승인 시 시간 반영

## 수정
- 순수 함수 `applyBulkTimeToSchedule(sched, busName, location, newTime)` 신설 (`lib/utils/vehicle-schedule.ts`).
  - 이 호차(+위치)를 타는 요일 = `targetDays` 에만 시간 적용.
  - 다른 호차를 타는 요일(`otherDays`)이 남아있으면 → 기존 공유 `_time`을 그 요일들의 `{요일}_time`으로 **먼저 이관**한 뒤, targetDays만 `{요일}_time=newTime` 설정하고 공유 `_time` 제거 → **요일별 모드 전환으로 다른 호차 시간 보존**.
  - 단일 호차 전 요일이면 기존처럼 공유 `_time` 하나로 통일.
- 위 4개 핸들러를 모두 이 헬퍼로 교체. 죽은 함수 `clearPerDayTimes`·미사용 `getClassDays` 제거.

## 검증
- 신규 유닛테스트 4건(한휘 케이스 포함): 요일별 다른 호차에서 3호차 시간 변경 시 6호차(화수목금) 시간 보존 확인.
- tsc 0 · eslint 0 · vitest **111/111**.
- 라이브 한휘 dep_schedule 시뮬레이션: 헬퍼가 3호차 요일만 신규시간, 6호차 요일은 기존시간 보존(요일별 모드 전환) 확인.

## 주의 / 후속
- **이미 깨진 데이터는 코드 수정으로 자동 복구되지 않음**: 한휘의 현재 dep_schedule은 과거 버그로 6호차 시간이 이미 3호차값(15:06)으로 덮인 상태. 배포 후 **6호차(화목) 올바른 하차시간을 한 번 재입력**하면 정상화됨(앞으로는 안 덮임).
- 시스템 공통 로직이라 **전 캠퍼스 동일 적용**.

# 차량관리 정류장명 변경이 적용되지 않던 문제 수정 (2026-06-18)

## 증상
노선 > 등원 > 유치부 > 4호차 > 고급설정 > **정류장명 변경**에서 새 이름으로 "변경"을 눌러도
노선에 반영되지 않음(새로고침해도 옛 이름이 그대로 돌아옴).

## 근본 원인 (다층)
정류장명 변경은 `renameStop`(프론트) → `PATCH /api/campus/stop-coords`(서버)로 동작하는데,
노선에 표시되는 정류장명의 출처는 **3곳**(학생 enrollment 위치 ∪ 등록정류장 ∪ 좌표키)인데
일부만 갱신하고 있었다.

1. **프론트 미갱신 (직접 원인)** — `RouteMapView.tsx`의 `renameStop`이 PATCH 후
   로컬 `coords`/`stopAddress`만 바꾸고, 다른 모든 변경 핸들러가 호출하는
   `refreshBothDirGroups()` / `loadData()` / `reloadRegisteredStops()`를 **호출하지 않음**.
   → 서버가 바꿔도 화면의 정류장 목록(서버 파생)은 옛 이름 그대로. `res.ok` 확인도 없었음.
2. **등록정류장 미변경** — PATCH가 `campus_stop_coords`와 `class_enrollments.{요일}_loc`만 바꾸고
   `campus_registered_stops.stop_name`을 안 바꿈. 유치부 노선은 빈 정류장(등록정류장)을 쓰는 경우가
   많아, 새로고침 시 등록정류장의 옛 이름이 다시 표시됨.
3. **정확일치 한계** — enrollment `{요일}_loc` 비교가 `=== oldName` 정확일치라
   가져온 데이터의 시간 프리픽스("08:57 중계1동…")·이중공백 변형을 놓쳐 매칭 실패.
4. (보너스) `pickup_overrides.location`(오늘만 임시위치)도 미변경.

## 수정
- `lib/utils/stop-name.ts`: 순수 함수 `splitLocTime`(시간 프리픽스 분리·보존),
  `renameStopInSchedule`(시간프리픽스/공백차 무시하고 정류장명만 치환) 추가. 단위테스트 +9.
- `app/api/campus/stop-coords/route.ts` PATCH:
  ① enrollment 치환을 `renameStopInSchedule`로 교체(프리픽스/공백 안전)
  ② `campus_registered_stops` 이름변경(새 이름 upsert로 병합 후 옛 이름 삭제 — 유니크 충돌 회피)
  ③ `pickup_overrides.location` 이름변경
- `app/(campus)/campus/vehicles/RouteMapView.tsx` `renameStop`:
  `res.ok` 확인(실패 시 로컬 안 바꾸고 알림) + 성공 시
  `refreshBothDirGroups()`/`loadData()`/`reloadRegisteredStops()`로 서버 파생 데이터 재조회.

# 2026-06-15 HQ 대시보드 캠퍼스별 현황 ≠ 캠퍼스 실제 (1000행 한도)

## 증상 (Raw/0615/오류3/가1.JPG)
HQ 대시보드 "캠퍼스별 현황" 카드의 수강생·유치부·초등부가 각 캠퍼스 실제 현황과 안 맞음.
- 송도: 카드 111(유치부5·초등부106) ↔ 실제 400(144·256)
- 목동매그넷: 카드 0 ↔ 실제 355
- 대전 162↔815, 수지 56↔580, 정발 51↔320, 중계 123↔283 등 다수.

## 원인 — Supabase 1000행 서버 한도
`app/api/hq/stats/route.ts` 가 **전 캠퍼스 enrollment 를 한 번에** 조회:
```
service.from('class_enrollments').select(...).in('class_id', classIds).eq('is_waitlist', false).limit(10000)
```
PostgREST 는 단일 select 를 서버측 max-rows(=1000)로 자른다 → `.limit(10000)` 무효, **1000행만** 반환.
최신월 전체 enrollment ≈ 3,618행이라 ~2,600행 누락 → 큰/뒤 캠퍼스가 과소·0 집계.
(per-campus roster 는 한 캠퍼스만 조회 <1000 이라 정상 → "HQ ≠ 캠퍼스" 비대칭 발생.)
※ 이미 알려진 함정(메모리: 정류장 마이그 때 2722행>1000 누락 → .range 페이지네이션으로 해결). stats 라우트만 미적용이었음.

## 수정 — .range() 페이지네이션
`fetchAllRows<T>(makeQuery)` 헬퍼 추가: `.range(from, from+999)` 로 1000행씩 끝까지 수집(안정 정렬 위해 `.order('id')`).
적용: `allClasses`, `prevClasses`, `allEnrollments`, `prevEnrollments` (1000을 넘길 수 있는 조회).
- `allEnrollments` 누락이 직접 원인(수강생/유치부/초등부/오늘 등하원 카운트 전부 영향).
- `allClasses`(현재 317, 성장 대비)도 페이지네이션.
- `allSessions`(현재 최신39·전체~120, 1000 한참 미만)는 유지(추후 1000 근접 시 동일 처리 필요).

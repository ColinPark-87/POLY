# 2026-06-15 캠퍼스 삭제 FK 수정 + 반편성현황 재업로드 덮어쓰기 확인

## 배경
HQ에서 보고된 2건:
1. **캠퍼스 삭제가 안 됨** — HQ 캠퍼스 관리에서 "삭제"를 눌러도 삭제되지 않음.
2. **반편성현황(개설반) 재업로드가 "추가"처럼 보임** — 잘못 올린 파일을 새로 올릴 때
   기존 삭제 안내 없이 누적되는 듯 함.

## 문제 1 — 캠퍼스 삭제 실패

### 원인 (systematic-debugging)
`app/api/hq/campuses/[id]/route.ts` 의 `DELETE` 가 단순히
`service.from('campuses').delete().eq('id', id)` 만 호출.
그러나 `campuses(id)` 를 참조하는 자식 중 일부가 `ON DELETE CASCADE` 가 **아님**
(`supabase/migrations/001_initial_schema.sql`):
- `users.campus_id`, `leave_grants/leave_requests/leave_records.campus_id`, `holidays.campus_id` → cascade 없음
- `campuses.principal_id → users(id)` (자기참조)
- `pickup_overrides.created_by`, `leave_requests.reviewed_by` → `users(id)` 를 cascade 없이 참조

직원이 있는 캠퍼스(=대부분)는 `users` FK 위반(Postgres 23503)으로 삭제 실패 → 400 → UI alert.
campus_* 운영 테이블(students/buses/sessions/classes/enrollments/overrides/registered_stops)은
cascade 라 차단 원인이 아님. (참고: `001_initial.sql` 과 `001_initial_schema.sql` 이 FK 동작이 상충 →
운영 DB 정확한 상태 불확실 → FK 동작에 의존하지 않는 코드레벨 명시 삭제로 해결.)

### 수정
직원 영구삭제(`employees/[empId]/route.ts`)와 동일한 "자식 먼저 삭제" 패턴. FK 안전 순서:
1. 캠퍼스 소속 `users` id 수집
2. `campuses.principal_id = null` (자기참조 해제)
3. campus_id 기준 비-cascade/유저참조 자식 삭제:
   `leave_records`, `leave_requests`, `leave_grants`, `holidays`, `pickup_overrides`, `campus_stop_coords`
4. `users` 삭제 (실패 시에만 400 반환)
5. best-effort 고아 auth 계정 정리 (`auth.admin.deleteUser`)
6. `campuses` 삭제 → 남은 campus_* 테이블 cascade 자동 제거
응답에 `deletedUsers` 포함. 미지의 비-cascade 참조가 남으면 최종 삭제 에러 메시지를 그대로 반환(현재보다 항상 개선).

UI(`app/(hq)/hq/campuses/page.tsx handleDelete`)는 이미 confirm+alert 처리 → 변경 없음.

## 문제 2 — 반편성 재업로드 덮어쓰기 확인

### 원인
`app/api/campus/class-roster/import/route.ts` 는 **이미** 해당 월(month) session/class/enrollment 를
삭제 후 재삽입(완전 덮어쓰기). enrollment 는 실제로 누적되지 않음. 단 (a) 삭제/교체 확인 메시지 없음,
(b) 학생·호차는 월 공유 엔티티라 미삭제 → 잔존이 "추가됨"으로 보임.

### 결정 (사용자)
**"해당 월 반편성만 교체 (안전·권장)"** — 학생·호차는 건드리지 않음.

### 수정
- **확인 메시지**(window.confirm) 추가:
  - `app/(campus)/campus/import/page.tsx handleRosterSubmit` (기존 confirm 없었음 → 신규)
  - `app/(hq)/hq/import/page.tsx` 반편성 제출 (기존 캠퍼스 확인 문구에 운영월 교체 안내 추가)
  - 문구: "'{운영월}'의 기존 반편성 데이터(세션·반·수강배정)가 모두 삭제되고 이 파일로 완전히 교체됩니다. (학생·호차 정보는 유지)"
- **교체 가시화**: 라우트가 삭제 건수 집계 → 응답 `replaced_sessions`, `replaced_enrollments`.
  결과 배너에 "↻ 기존 수강배정 N건 삭제 후 교체" 표시.
- 학생·호차 미삭제(유지). 운영월 문자열을 다르게 입력하면 다른 월 데이터가 남는 점은 확인 문구에 운영월 노출로 완화.

# 지도에서 정류장 추가 → 전체 연동 (C안 구현)

작업일: 2026-05-29 · 담당: Colin

## 목표
지도에서 정류장을 추가하면, 그 정류장이 단순 후보가 아니라
**① 탑승장소 및 호차설정**, **② 개설반 현황의 학생 정류장 매칭**에 전부 반영되도록 연동.

## 데이터 흐름
```
[지도 FAB '정류장 추가'] → 모달(호차·방향·정류장명·시간 + 지도 위치 지정)
        │  POST /api/campus/registered-stops  (+ 좌표는 campus_stop_coords)
        ▼
   campus_registered_stops  (빈 정류장 마스터 / 학생 0명)
        ├─→ ① 탑승장소 및 호차설정 (vehicles Page4)  — registeredStops union 으로 이미 소비
        └─→ ② 개설반 현황 학생 정류장 select        — 이번에 신규 연동
```

## 버그 수정 (2026-05-29 추가)

### 증상
정발 캠퍼스로 진입했고 지도/시스템은 정발인데, 호차 카드 노선이 **중계** 정류장으로 매칭되어 표시됨.

### 근본 원인 (캠퍼스 데이터 staleness)
부모 `vehicles/page.tsx`(371-382)가 `/api/campus/me`로 **campusId를 비동기로 늦게 설정** → 첫 렌더에는 `campusId=undefined`. 그런데 `RouteMapView`의 노선 로더 두 곳이 `campusId`를 사용하면서 의존성에서 누락:
- `loadData`(노선 카드용 `groups`/`buses`): 의존성 `[dir]` → campusId 도착해도 재요청 안 함
- `bothDirGroups` 마운트 effect: 의존성 `[]` → 마운트 1회만 로드

campusId=undefined로 첫 요청 시 campus_id 파라미터 없이 호출 → 다른 캠퍼스(중계) 데이터가 잡힘. 이후 campusId가 정발로 바뀌어도 재요청이 없어 중계 데이터가 유지됨. 반면 좌표·지도 effect는 `[campusId]`라 정발로 갱신 → "지도=정발, 노선=중계" 불일치.

### 수정
- `loadData` 의존성 `[dir]` → `[dir, campusId, cqs]`
- `bothDirGroups` 마운트 effect 의존성 `[]` → `[campusId, cqs]`
→ campusId 확정 시 노선 데이터가 올바른 campus_id로 재요청됨. (`refreshBothDirGroups`는 이미 `[campusId, cqs]`로 정상이었음)

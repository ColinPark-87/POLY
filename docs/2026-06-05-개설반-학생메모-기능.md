# 2026-06-05 개설반 현황 — 학생 메모 기능 (신규)

대상: `/campus/class-roster` (개설반 현황) → 반편성 현황관리 탭의 반별 카드 학생 칩
운영 중 시스템이라 백업 선행, 비파괴.

## 기획 확정 (사용자 선택)
- **단일 메모**(학생당 1개, 덮어쓰기)
- **반편성 카드에서만** 우클릭
- 아이콘 **호버=미리보기(툴팁), 클릭=편집**
- **데스크톱(우클릭) 전용** (모바일 미대응)

## 동작
- 반편성 카드의 학생 칩을 **우클릭** → 컨텍스트 메뉴(메모 추가/편집, 메모 삭제)
- 메모가 있으면 학생명 왼쪽에 **📝 아이콘** 표시
  - 아이콘 **호버** → 메모 내용 + 작성자·수정일 툴팁(native title)
  - 아이콘 **클릭** → 편집 팝업(textarea, 저장/취소/삭제, 최근 수정자·일자)
- 메모는 학생(campus_students) 단위 → 같은 학생이 여러 반에 있어도 모든 칩에 동일 표시
- 기존 칩 동작(클릭=상세모달, 드래그=반이동) 그대로 유지

## ⚠️ 배포 전 필수: DB 컬럼 추가 (Supabase SQL Editor에서 1회 실행)
```sql
ALTER TABLE campus_students
  ADD COLUMN IF NOT EXISTS memo TEXT,
  ADD COLUMN IF NOT EXISTS memo_updated_by TEXT,
  ADD COLUMN IF NOT EXISTS memo_updated_at timestamptz;
```
- 컬럼이 없어도 **명단 로딩은 깨지지 않음**(GET이 메모 없이 폴백). 단, 저장 시도 시
  컬럼이 없으면 저장이 실패하고 안내 경고가 뜬다. 따라서 위 SQL을 먼저 실행할 것.

## 변경 파일
- `app/api/campus/class-roster/route.ts` — GET enrollments select가 memo 컬럼 포함을
  시도하고, 실패 시 메모 없이 재조회(폴백)하여 명단 로딩이 절대 깨지지 않게 함.
- `app/api/campus/students/route.ts` — PATCH가 `memo`를 받도록 확장. 메모만 수정 시
  이름 필수검사 생략, `memo`는 trim→빈값이면 null, `memo_updated_by`=작성자(profile.name),
  `memo_updated_at`=now. 권한(canEditStudents)·캠퍼스 소유권(.eq campus_id) 그대로 유지.
  기존 이름/영어/학교/아파트 수정 경로는 영향 없음.
- `app/(campus)/campus/class-roster/page.tsx`
  - `Student` 타입에 memo 3필드 추가
  - 메모 상태(메뉴/에디터/draft/saving) + 핸들러(openMemoMenu/openMemoEditor/saveMemo/
    deleteMemo/applyMemoLocal) 추가. 저장 시 같은 학생 모든 enrollment에 낙관적 반영.
  - RosterTab에 `onStudentMemoMenu`/`onStudentMemoIcon` 전달, 칩에 `onContextMenu` +
    📝 아이콘(title 툴팁/클릭 편집) 추가.
  - 컨텍스트 메뉴는 전역 click/contextmenu/scroll 리스너로 닫힘(다른 칩 우클릭 시 즉시 이동).

## 권한
`canEditStudents`(원장/관리자/상담/KT/`perm_class_roster` 등) 보유자만 추가·수정·삭제.
권한 없는 사용자가 저장 시 서버 403 → 경고.

## 평가·검수 (독립 리뷰 에이전트)
- **Critical/High 없음.** 보안(XSS: 메모는 JSX 텍스트/`title` 속성으로만 렌더 → 자동 이스케이프,
  쓰기는 파라미터라이즈드), 정합성(학생 id 기준 메모 → 오학생 배정 없음), 권한/소유권,
  명단 로딩 폴백, 기존 이름수정 비회귀 모두 통과.

  리스너 방식으로 수정 완료**(칩 우클릭은 stopPropagation이라 새 위치로 바로 이동).

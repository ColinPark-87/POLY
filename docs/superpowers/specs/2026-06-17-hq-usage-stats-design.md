# HQ 파일럿 사용현황(접속·활동 통계) 탭 — 설계

작성 2026-06-17 / 대상 앱: leave-system (https://poly-system.vercel.app) / 담당: Colin
스택: Next.js 16 (App Router) + Supabase(Postgres) + Vercel CLI 배포

## 1. 목적 / 비목적

**목적**
- 전 캠퍼스 파일럿 중 **어느 캠퍼스/사용자가 얼마나 꾸준히 쓰는가**를 HQ에서 한눈에 본다.
- HQ 좌측 사이드바에 **별도 탭**(hq_admin 전용)으로 기간별·캠퍼스별·사용자별 통계 + 차트 + 출력(CSV/인쇄).

**집계 대상 = 활동 이벤트 2종**
- `login`: 로그인 성공
- `edit`: 개설반 현황 / 차량관리에서의 저장(수정·업데이트) 발생 — **요청당 1건, 내용(무엇을 바꿨나)은 저장하지 않음**.

**비목적 (YAGNI)**
- 변경 내용/diff, 실패 로그인, 로그아웃·세션·페이지 조회 추적.
- 캠퍼스 사용자에게 노출(이 탭은 HQ 전용).
- 새 차트 라이브러리 도입(기존 스타일의 CSS/SVG 막대로 충분).
- 로그 보존기간 자동 정리(파일럿 기간 데이터량 적음 → 전량 보관).

## 2. 데이터 모델 — 신규 테이블 1개 (기존 무손상)
```sql
create table if not exists public.usage_logs (
  id          bigint generated by default as identity primary key,
  event_type  text not null,                 -- 'login' | 'edit'
  area        text,                            -- edit일 때 'roster' | 'vehicles' (login이면 null)
  campus_id   uuid,                            -- HQ 계정 등 캠퍼스 없으면 null
  user_id     uuid,
  user_name   text,
  role        text,
  created_at  timestamptz not null default now()
);
create index if not exists usage_logs_campus_time_idx on public.usage_logs (campus_id, created_at);
create index if not exists usage_logs_time_idx on public.usage_logs (created_at);
```
> 내용 컬럼 없음(이벤트 사실만). 마이그레이션은 Supabase SQL Editor 수동 실행.

## 3. 기록 (비차단 — 기존 동작 절대 안 깸)
**헬퍼 `lib/usage-log.ts`**
```ts
export type UsageArea = 'roster' | 'vehicles'
export async function logUsage(service, e: {
  event_type: 'login' | 'edit'; area?: UsageArea
  campusId?: string | null; userId?: string | null; userName?: string | null; role?: string | null
}): Promise<void> {
  try { await service.from('usage_logs').insert({ ...e ... }) } catch { /* 무시: 로그 실패가 본동작을 막지 않음 */ }
}
```
- 항상 try/catch로 격리, 절대 throw 안 함. 응답 흐름을 막지 않도록 호출(실패해도 본 동작 정상).

**호출 지점**
| 이벤트 | 위치 | area |
|---|---|---|
| login | `app/api/auth/login/route.ts` (signIn 성공 직후) | — |
| edit | `app/api/campus/vehicles/route.ts` POST(변경 액션 성공 시 1건) | vehicles |
| edit | `app/api/campus/stop-coords/route.ts` (POST/PATCH/DELETE) | vehicles |
| edit | `app/api/campus/registered-stops/route.ts` (POST/DELETE) | vehicles |
| edit | `app/api/campus/class-roster/route.ts` (변경 메서드) | roster |
| edit | `app/api/campus/class-roster/import/route.ts` | roster |
| edit | `app/api/campus/students/route.ts` (메모/수정 등 변경 시) | roster |

> 세부 액션마다가 아니라 **요청당 1건**. read 전용(GET)·검색은 기록 안 함.

## 4. 집계 API — `app/api/hq/usage/route.ts` (GET, hq_admin 전용)
- 입력: `?from=YYYY-MM-DD&to=YYYY-MM-DD` (기본 최근 7일).
- 권한: `profile.role === 'hq_admin'` 아니면 403.
- `usage_logs`를 기간 필터로 조회(1000행 초과 시 `.range` 페이지네이션) → 서버에서 집계:
  - `byCampus`: [{campus_id, campus_name, logins, edits, activeUsers, lastActiveAt}]
  - `byUser`: [{user_id, user_name, campus_name, role, logins, edits, lastAt}]
  - `byDay`: [{date, logins, edits}] (전체) + 캠퍼스별 일자 매트릭스(차트용)
- 캠퍼스명은 `campuses` 조인/맵으로 해석.

## 5. HQ 탭 UI — `app/(hq)/hq/usage/page.tsx`
- **사이드바**: `components/HqSidebar.tsx`에 `{ href:'/hq/usage', label:'파일럿 사용현황', icon:'📊' }` 추가(적절한 그룹).
- **기간 선택**: [최근 7일] [30일] [사용자지정 from~to] 토글.
- **요약 카드**: 전체 로그인 수 · 활동 수 · 활성 사용자 수(기간 내).
- **캠퍼스별 통계 표**: 캠퍼스 | 로그인 | 활동 | 활성 사용자 | 마지막 활동.
- **캠퍼스별 차트**: CSS/SVG 막대 — 캠퍼스별 활동량 + 일자별 추세(전체). 새 라이브러리 없음.
- **사용자별 집계 표**: 이름 | 캠퍼스 | 역할 | 로그인 | 활동 | 마지막 접속 (정렬: 활동 많은 순).
- **출력**: ① CSV 다운로드(캠퍼스별·사용자별 표를 UTF-8 BOM CSV로, 엑셀 호환) ② 인쇄용 보기(@media print, A4) — 기존 차량관리 인쇄 패턴 참고.

## 6. 위험 격리 (핵심 — "잘 도는 시스템 안 꼬이게")
- 기록은 전부 **비차단**(try/catch + 본 동작 응답을 막지 않음) → 로그인·저장 절대 안 깨짐.
- **신규 테이블만** 추가 → 기존 스키마/데이터/쿼리 무손상.
- 기존 엔드포인트는 성공 경로 끝에 `logUsage(...)` 한 줄만 추가(반환값·검증 로직 불변).
- 마이그레이션(테이블 생성)은 코드 배포와 별개로 먼저 수동 실행.

## 7. 테스트
- **단위(vitest)**: 집계 순수함수(`aggregateUsage(rows, campusMap)`) — 캠퍼스별/사용자별/일자별 합산·활성사용자(distinct)·마지막시각. CSV 직렬화 함수.
- **수동**: 두 캠퍼스 로그인 + 개설반/차량 저장 → HQ 탭 통계·차트·CSV 반영 확인.

## 8. 롤아웃 / 복구
- 순서: ① SQL 마이그레이션(usage_logs) → ② 코드 배포(`vercel --prod`) → ③ RESTORE.md·백업 브랜치 갱신.
- 복구: 코드 롤백 `vercel promote {이전}`. `usage_logs`는 부가 데이터(소실돼도 업무영향 없음). 미사용 시 테이블 drop 무해.

## 9. 추후
- 실패 로그인/보존기간 정리/캠퍼스 사용자 노출은 필요 시 별도.

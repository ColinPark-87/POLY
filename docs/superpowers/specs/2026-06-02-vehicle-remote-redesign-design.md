# 차량관리 "리모컨" 재설계 — 설계 문서

작업일: 2026-06-02 · 담당: Colin · 브랜치: `vehicle-remote-redesign`
복구 시점: 태그 `pre-remote-redesign-20260602` (커밋 eb57119)

## 1. 목표 / 문제

차량관리(`/campus/vehicles`)는 여러 세션(개설반 기준: 유치부·매일반·3일반·2일반 등) × 등원/하원을 다룬다. 현재는 보기마다 컨트롤 위치가 다르고(상단 탭 시스템/모바일/학생설정 + 지도 우측 노선/오늘/변경/탑승장소설정/호차설정), 세션을 하나씩 골라 전환해야 해서 한 화면에서 흐름이 끊기고 깔끔하지 않다.

**목표:** 지도를 항상 중심에 둔 채, 모든 세션·기능을 **하나의 플로팅 "리모컨"**으로 조작. 데이터가 많은 작업(학생설정)은 큰 모달+검색으로 분리. 데이터 계층/개설반 연동은 그대로 유지(UI만 재설계).

## 2. 핵심 결정 (확정)

- **레이아웃:** 지도 full-bleed + **플로팅 리모컨**(R2). 끌어 이동·접기·위치 기억. 상단 3탭(시스템/모바일/학생설정) 제거.
- **표시 모델:** **M1 — 한 세션 포커스.** 한 번에 한 세션만 지도에. 세션 내 호차는 1대/다중/전체(색상 구분) 표시. 세션 전환은 리모컨 1탭.
- **세션 단위:** **개설반 현황(`class_sessions`) 기준 동적.** 하드코딩(유치부/초등부) 안 함. 캠퍼스에 실제 개설된 세션을 그대로 버튼화.
- **학생설정:** **별도 모드 버튼** + **큰 모달 + 학생 검색**(이름/영문명). (통합형 아님 — 입구 명확)
- **데이터/연동:** `class_enrollments`(+세션 `class_sessions`) 그대로. 차량관리 변경 → 개설반 현황 반영(현 동작 유지). "오늘" 임시배정만 `pickup_overrides`(영구 아님)로 분리되는 현 규칙 유지.

## 3. 리모컨 (컨트롤러)

플로팅 카드. 항상 떠 있고 조작 전용(데이터 표시는 시트/모달이 담당).

구성(위→아래):
1. **상태 화면** — 현재 보기 요약: 세션·방향·호차·인원. 표시 전용.
2. **모드 5버튼** — `노선 · 오늘 · 학생 · 변경 · 설정`
3. **공용 선택부** (모드 바뀌어도 유지):
   - 등원/하원 토글
   - **세션 버튼** (개설반 기준 동적 목록)
   - **호차 버튼** (다중 선택) + **전체 호차** (그 세션 모든 호차 동선 색상 표시)
4. **접기** — 작은 캡슐(선택 요약)로 접어 지도 최대화. 드래그로 위치 이동, 위치 기억(localStorage).

선택부(등하원+세션+호차)는 노선/오늘/학생 모드에서 공유된다. **변경/설정 모드에서는 공용 선택부를 숨긴다**(해당 모드와 무관).

## 4. 모드별 동작

- **노선** (기본): 선택 세션 노선을 지도에 표시(M1, 전체 호차 색상 가능). 호차를 탭하면 그 호차 **명단 시트(좁게)**가 지도 옆에 슬라이드 — 지도 유지하며 빠른 확인/수정. 명단 시트에서 "크게 편집" → 학생 모달.
- **학생**: **큰 모달**(거의 전체 화면). 상단 **학생 검색(이름/영문명, 즉시 필터·하이라이트)** + 세션/방향 필터(리모컨 선택 상속). 본문은 **호차별 학생 그리드** — 학생 카드 **드래그로 호차 이동**, 카드 탭 → 시간·요일·정류장 수정, 호차별 탑승자 추가, 일괄 시간. 모든 변경은 영구(`update_enrollment_schedule` 등) → 개설반 동기화.
- **오늘**: 날짜 선택 + 그날 등하원/결석/임시배정(override: 오늘만 / 앞으로 변경). 현 "모바일/오늘" 기능 흡수.
- **변경**: 차량변경 요청 승인/거절 목록(현 "변경" 기능).
- **설정**: 하위 2탭 — **탑승장소설정**(캠퍼스·정류장 좌표, 일괄입력, 자동검색) / **호차설정**(차량 추가·수정·삭제). 현 탑승장소설정/호차설정 그대로 이관.

## 5. 상세 표시 규칙 (시트 vs 모달)

- **명단 시트(좁게):** 노선 모드에서 호차 탭 시. 지도와 공존(지도 줄고 시트 옆에). 한 호차 빠른 보기/수정.
- **학생 모달(크게):** 학생 모드 또는 명단 시트 "크게 편집". 검색 포함, 자료 많을 때.
- **설정/오늘:** 자체 패널(시트). 지도와 무관하게 동작.
- 리모컨은 어떤 경우에도 떠 있어 세션·모드 전환 즉시 가능.

## 6. 컴포넌트 구조 (의도)

`RouteMapView.tsx`(현재 4천 줄 규모, 너무 큼)를 작업하면서 다음으로 분리:
- `vehicles/Remote.tsx` — 플로팅 리모컨(상태화면·모드·선택부·접기/드래그/위치기억). 상태는 상위에서 props/콜백.
- `vehicles/StudentEditModal.tsx` — 학생 큰 모달(검색·호차별 그리드·드래그 이동·편집). 데이터는 `class-roster` 편집 액션 재사용.
- `vehicles/RosterSheet.tsx` — 노선 모드 호차 명단 시트(좁게).
- `vehicles/SettingsPanel.tsx` — 탑승장소설정/호차설정 2탭(기존 Page4/5 이관).
- `vehicles/MapCanvas.tsx` — 지도 렌더(노선/마커/TMAP). 기존 지도 effect 이관.
- 상태/데이터 로직은 상위(page 또는 컨테이너 훅 `useVehicleState`)로 끌어올려 단방향 흐름.

원칙: 각 단위는 "무엇을 하는지·어떻게 쓰는지·무엇에 의존하는지"가 명확하고 독립 테스트 가능해야 한다. 큰 파일 분해는 이 작업 범위에 포함(현재 RouteMapView 비대).

## 7. 동작 세부

- 리모컨 위치/접힘 상태: `localStorage`에 저장(캠퍼스별 키).
- 세션 색상: 개설반 세션명 → 색 매핑(기존 `getSessionColor`/`getRunColor` 재사용).
- "전체 호차" 토글 시 세션 내 호차별 색으로 동시 표시(M1 내 다중).
- 학생 모달 변경 후 지도/시트 자동 갱신(공용 상태 갱신).
- 데이터 fetch는 기존 `/api/campus/vehicles`·`/api/campus/class-roster` 재사용(신규 API 최소화).

## 8. 범위 밖 (YAGNI)

- 여러 세션 동시 오버레이(M2/M3) — 채택 안 함(필요 시 후속).
- TMAP/노선 알고리즘 변경 — 이번 범위 아님(현재 서울 프록시 유지).
- 개설반 현황 페이지 자체 변경 — 차량관리만 재설계.
- "오늘 override 영구반영 자동화" 등 데이터 규칙 변경 — 미요청, 제외.

## 9. 테스트 / 검증

- 단위: 리모컨 선택 상태 머신(세션/방향/호차/모드 전환), 학생 모달 검색 필터, 드래그 이동→영구 반영 액션 호출.
- 통합/수동: 세션 전환·전체 호차·호차 탭 시트·학생 모달 검색/이동·오늘 override·변경 승인·설정 2탭. 개설반 현황과 양방향 반영 확인.
- 회귀: 기존 차량관리 기능(배정/삭제/탑승자추가/일괄시간/백업) 동등 동작.
- 빌드: `npx tsc --noEmit` + `npm run build` + `vitest run` 통과 후 배포.

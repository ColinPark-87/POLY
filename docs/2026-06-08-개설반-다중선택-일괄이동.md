## 설계 결정 (브레인스토밍)

- **선택 방식: Ctrl/Cmd+클릭 = 토글, Shift+클릭 = 범위(같은 반 카드 순서)**.
  평클릭=학생 상세(기존), 우클릭=메모(기존)는 그대로. UI 군더더기 없음, 데스크톱 전용
  (기존 드래그도 HTML5 네이티브라 데스크톱 전용 — 일관).
- **부분 실패: 성공한 건만 옮기고 결과 알림**(올-오어-낫씽 아님). 차량 `bulk_*` 패턴과 동일.
- 스케줄: 단일 드래그처럼 **각 학생의 기존 arr/dep 스케줄을 보존**(모달 없음 — 다수엔 비현실적).
- 여러 반 카드에서 골라 한 반으로 떨구는 **교차 카드 선택**도 자연히 지원(서버가 임의 id 배열 처리).

## 구현

### 순수 로직 분리 — `lib/utils/roster-multimove.ts` (+ 단위 테스트 13개)
- `toggleSelection(set, id)` — Ctrl+클릭 토글(불변).
- `rangeIds(orderedIds, anchor, target)` / `applyRange(...)` — Shift+클릭 범위(양끝 포함, 역방향 OK).
- `partitionBulkMove(candidates, requestedIds, targetClassId, targetStudentIds)` — 서버 분류:
  후보없음(타캠퍼스/삭제)·이미 대상반·대상반 학생 중복(기존+배치 내 동일학생 중복)을 건너뛰고
  나머지를 movable로. **같은 학생의 enrollment가 둘 이상 선택돼도 한 명만 이동**(중복 삽입 방지).

### 서버 — `app/api/campus/class-roster/route.ts` 신규 액션 `bulk_move_students`
- body `{ enrollment_ids: string[], to_class_id }`. 대상 반 소유권 1회 확인(403),
  후보 enrollment(자기 캠퍼스만)·대상반 기존 학생 1회 조회 → `partitionBulkMove`로 분류 →
  movable만 per-row 삭제+삽입(스케줄/하이라이트 보존)+이력(`transferred`) 기록.
  반환 `{ moved, skipped:[{id,name,reason}] }`. 한 건 실패해도 나머지 진행(failed 합산).
- 기존 단일 `move_student`는 그대로.

### 클라이언트 — `app/(campus)/campus/class-roster/page.tsx`
- 페이지: `handleBulkDrop(ids, toClassId)` 추가(POST→`load()`→결과 반환), `onBulkDrop` prop 전달.
- RosterTab: `selectedEnrIds:Set`/`anchorEnrId`/`dragIdsRef`/`bulkMsg` 상태.
  - 학생 칩 onClick → `handleStudentChipClick`(Ctrl/Cmd 토글·Shift 범위·평클릭 상세+선택해제).
  - onDragStart → `startStudentDrag`: 선택에 포함된 칩이면 선택 전체, 아니면 그 한 명만 드래그
    (단일 드래그 동작 유지). 여러 명이면 "👥 N명 이동" 드래그 고스트.
  - 반 카드 onDrop → `dropStudents`: 1명이면 기존 `onDrop`, 여러 명이면 `onBulkDrop`+토스트.
  - 선택 칩 하이라이트(파란 톤+`✓`+ring), 하단 플로팅 바("👥 N명 선택 · 해제(Esc)"),
    결과 토스트("N명 이동 완료 · M명 건너뜀(사유)"), Esc·검색어 변경 시 선택 해제.

비파괴: 단일 드래그·클릭 상세·우클릭 메모·반/세션 순서 드래그·대기자 행 전부 기존대로.
